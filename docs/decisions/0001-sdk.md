# ADR 0001: MCP SDK v2, Zod v4 and toolchain versions

Status: accepted (stage 1), 2026-11-17

## Decision

- **MCP SDK:** `@modelcontextprotocol/server` and `@modelcontextprotocol/client` **2.4.0**, pinned exactly. v1 (`@modelcontextprotocol/sdk`) is not used.
- **Schemas:** Zod 4, imported as `zod/v4`. Tool schemas are passed as `z.object(...)`; the raw-shape form is deprecated in v2.
- **Runtime:** published packages declare `node >=20` (the SDK's own engine range). The dev toolchain needs Node ≥ 22.12 because Vitest 5 requires it. CI runs tests on Node 22 and 24, and a separate job runs the built server on Node 20.
- **TypeScript:** 6.0.x. TypeScript 7 is out, but `typescript-eslint` 8.73 supports `<6.1`, so 7 waits for typescript-eslint support.
- **Module format:** ESM only (the SDK is ESM-first), `module: NodeNext`, project references with `tsc -b`.

## Verified against the installed 2.4.0 package

- `serveStdio(factory, options)` from `@modelcontextprotocol/server/stdio` serves stdio. It takes a **factory** that returns an `McpServer` and pins one instance per connection. It also serves 2025-era clients that open with `initialize` (`legacy: 'serve'` is the default), which matters for clients that have not moved to the 2026-07-28 protocol yet.
- `McpServer.registerTool(name, { title, description, inputSchema, outputSchema, annotations }, cb)`.
- The SDK validates input: invalid arguments come back as a result with `isError: true` and the handler does not run.
- `structuredContent` is validated against `outputSchema` for successful results only. A result with `isError: true` may carry a different `structuredContent` shape. We rely on this for `ToolError` (spec §4).
- Annotations such as `readOnlyHint` are passed through to `tools/list` as hints. The SDK does not enforce them, so `core/runtime/policy` does.
- The client side uses `Client` from `@modelcontextprotocol/client` with `StdioClientTransport` from `@modelcontextprotocol/client/stdio`. `InMemoryTransport` is also exported for in-process tests.

## Deferred

- SQLite driver (`node:sqlite` or `better-sqlite3`): decided in stage 2, when the audit log and cache are built.
- Elicitation (needed for the write-confirmation protocol, spec §6.3): v0.3.
